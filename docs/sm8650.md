# SM8650 platform layer

Owner: sm8650 (docs/io-stack.md section 6). This covers the GPIO, pinctrl,
clock and regulator implementations behind `kshim/gpio.h`, `pinctrl.h`,
`clk.h` and `regulator.h`, the SoC tables in `kernel/soc/`, and SM8650
support in the existing interrupt, key and storage layers. Nothing here has
run on hardware.

## Behaviour

- **Inherit first.** A pad, clock or rail that already has the wanted state
  is not written. Equal register values are skipped.
- **Snapshots.** The registry snapshots each TLMM pad (CFG and IO) or PMIC
  GPIO (0x40-0x46, 0x4a) before the first write. A consumer's last
  `kshim_gpio_free()` restores the pad unless pinctrl touched it.
  `kshim_gpio_restore_all()` restores what is left, newest first. Clocks
  snapshot the enable word, the RCG configuration and the BCRs they touch.
  Regulators restore fixed rails through the GPIO layer, and RPMh rails
  return to the observed own-DRV request.
- **TLMM layout.** SM8150/SM8250 pad offsets and function names come from
  CrDK `CrAndroidPin`. SM8650 is linear (pad × 0x1000, pads 0-209), with
  mux slots from `pinctrl-sm8650.c` facts. Selecting a function on an SM8650
  EGPIO pad sets EGPIO enable (bit 12) so the apps TLMM owns it. Pads in
  the DT `gpio-reserved-ranges` (NFC on both boards) are refused.
- **PMIC GPIO.** CrDK PmicGpioLib handles the subtypes, using a single-pin
  controller and a context on the stack for each operation. It runs over
  `kshim_qcom_pmic_gpio_read8/write8`, which write only to the GPIO
  configuration registers of a peripheral whose TYPE is GPIO. Pinctrl
  states on PMIC GPIOs stay inherited.
- **Clocks.** These are SM8650 GCC/TCSR rows keyed by dt-binding ID or Linux
  name, plus SM8150/SM8250 Android IDs through `CrAndroidClock`. An inherited
  running branch is never written or retuned. `kshim_clk_set_rate_cxo()`
  picks a verified CXO DFS level, or sets SRC_SEL 0 / divider 1 on a plain
  RCG (the CrDK `clock_poll` policy).
- **RPMh.** Mainline resource names are `ldo`/`smp`/`bob` + `qcom,pmic-id`
  + index (`ldob14`). Android uses `qcom,resource-name`. Votes go through CMD
  DB and CrDK's polled TCS API. Before the first vote the driver reads the
  apps DRV's own request back with an RPMh read on a borrowed idle ACTIVE
  TCS. This uses the same claim/snapshot/restore as `CrRpmhPollWrite`, and
  CrDK `RpmhRailObserveLib` needs the interrupt-driven RpmhLib core, which
  this port does not run. A rail observed enabled inside its DT range is
  inherited-on. A vote whose inherited value could not be read is kept at
  handoff and logged. A TCS that never completes stays claimed, and RPMh is
  then refused.

## SM8650 in the existing layers

| Layer | Change |
| --- | --- |
| GIC | Already DT-driven; `#interrupt-cells = 4`, redistributor stride 0x40000 are parsed (host-tested) |
| TLMM summary | `qcom,sm8650-tlmm` (210 pads); INTR_CFG apps target at bits 10:8 (wake bits 6/7 preserved); DT reserved pads refused |
| PDC | Built-in `qcom,sm8650-pdc` ranges for DTs without `qcom,pdc-ranges` |
| SPMI | Multi-reg peripherals (PMK8550 pon `hlos`/`pbs`); arbiter v7 is CrDK SpmiLib's runtime-detected path |
| Keys | PMK8550 PON gen3 power (bit 7) and resin (bit 6) at 0x1310; pm8550_gpios 6 RT_STS 0x8d10 |
| Console | uart15 (`serial0`, 0x89c000, `qcom,geni-debug-uart`) through the existing DT probe |
| Storage | Mainline UFS `power-domains` resolve to the GDSCR (ufs_phy_gdsc, GCC + 0x77004) so a live UFS can be inherited |

## Board profiles

`configs/qrd8650_defconfig` and `configs/ayaneo_pocket_s2_defconfig` build
with the LVGL menu, the SM8650 interrupt cascades and the keys. Since the
integration (`integrate/io-stack`) they also enable their I/O stack: the QRD
gets the platform layer, QUP/GENI SPI and the GT9916; the Pocket S2 gets
storage and the firmware loader (ext4/F2FS; EROFS is GPL opt-in and left
off), the platform layer, the Qualcomm PCIe host, xHCI with the Renesas
download, hub and HID, and QUP/GENI I2C with the GT911. With the LVGL menu
neither image fits the 4 MiB Manifest slot any more ("kShim runtime exceeds
image slot"); slot size is not treated as a blocker, and a link with a
larger scratch slot resolves every symbol.

## Not covered

- SM8650 pcie1 `PcieTargetContext` (the QMP gen4x2 PHY tables for a cold
  PCIe init) is provided by the pci implementer in
  `kernel/drivers/pci/qcom_sm8650.c`, not here. The clocks, resets, GDSC,
  rails and GPIOs it names all resolve through this layer.
- PMIC GPIO interrupts and PMIC pinctrl states.
- ICC/BCM and CX votes (docs/io-stack.md section 2).
